実装
1 npm run build / Netlify commandをnetlify-safe-build.jsへ統一。
  CONTEXT=productionだけが実バックエンドを生成する。
  deploy-preview / branch-deployはcontext別commandで--previewを強制。
  不明・欠落・devのcontextも安全モード。NETLIFYの有無だけでは本番を許可しない。
2 Netlify Functions directoryをnetlify/safe-functionsへ変更。
  毎ビルドで古い生成物を消して拒否用Functionsを先に作り、成功したproduction buildだけ
  本番用Functionsを生成する。元ファイルと同じ階層で相対importを維持する。
  本番用17ファイルは元ファイルとbyte一致。既存のpath/schedule/認証コードは維持。
3 プレビュー用17 Functionsはimport・環境変数読取・外部通信なしで常に403。
  runtime CONTEXTが未設定でもproductionに誤設定されても拒否する。
  クライアント提供のheader/URL/flagを許可判断に使わない。
  管理画面の別名pathも拒否。cronのconfigは生成せず、手動呼出も403。
  実行時CONTEXTが保証されるという前提には依存しない。
4 プレビュービルドの子プロセスはOS実行に必要な変数だけを許可し、業務用秘密変数を渡さない。
  fetch / HTTP(S) / socket接続を遮断。Sanityにも接続しない。
  元のビルド処理・CMSのGROQ・医学記事・診断ソースは変更していない。
5 プレビューのanalytics-bootstrapはローカルモードだけを設定し、Googleタグを読み込まない。
  site-configのmeasurement IDはnull。CSPで外部script/connect/frame/広告pixelを制限。
  診断・広告の既存ローカル計測先を再利用し、DB保存・AI・同期・管理は停止。
6 プレビュー全HTMLにnoindex/nofollow/noarchiveと停止中の案内を追加。
  全静的パスのX-Robots-TagとCSPをdist/_headersへ生成。
  競合を避けるためTOMLの重複header定義を削除。元の_headersに同一の本番security/cache定義が
  あるため、本番のheader値は維持される。canonicalや本番SEO生成処理も変更しない。
  robots.txtはnoindexをクローラーが読めるようAllowにし、プレビューのsitemap申告はしない。
  robotsのDisallowだけでは検索結果からの除外を保証できない。
7 公開記事は「未取得」。0件取得成功とは扱わず、画面・buildログ・site-configで識別。
  プレビューは記事一覧の実データ照合・管理ログインの確認には使用できない。
8 既存CIへpreview:testを追加。npm testは外部通信を禁止。
  CI buildは保護された専用preloadから3件の非医学的ダミー記事を供給。
  本番CMSへ接続せず、既存36検証の「最低3記事」の検証を維持する。
  CI専用preloadはCI=true以外およびNETLIFY=trueで起動拒否。
  CIの成果物は医学記事として公開せず、実記事件数や実績として使用しない。

元の実バックエンドはプレビューの実行entryからimportされない。
included_filesに既存の分析ソースが含まれても実データや認証値は含めず、実行経路はない。
